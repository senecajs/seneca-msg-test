# Reference earlier replies

How to use the reply of one call in the parameters or the expected reply
of a later call, for example an id generated by the store.

## 1. Name the call whose reply you need

```js
{
  name: 'pear',
  pattern: 'cmd:add',
  params: { name: 'pear', price: 0.75 },
  out: { name: 'pear' },
},
```

When the reply arrives, the harness stores a call record under the name
`pear` in the reference context. The record has `out` (the reply),
`err`, `params`, `msg` (the message as sent), `meta` (the Seneca meta
data) and the patterns (see [the call record](../reference/references.md#the-call-record)).

## 2. Reference it in a later call

A string of the form `` `name:path` `` is replaced by the value at
`path` inside the record:

```js
{
  pattern: 'cmd:get',
  params: { id: '`pear:out.id`' },
  out: { name: 'pear', price: '`pear:out.price`' },
},
```

The path is a JavaScript property path: `out.id`, `out.items[1].id`,
`params.quantity`, `msg.role`, `meta.pattern`. A reference that makes up
the whole string keeps the type of the value: `` `pear:out.price` ``
is the number `0.75`, not the string `'0.75'`, which matters because
literal matching compares types.

## 3. Build strings and expressions

Text around a reference, or several references in one string, produce a
string; objects are inserted as JSON:

```js
params: { label: 'item-`pear:out.id`' }           // 'item-dpyruk'
```

A backtick expression without a colon is evaluated as JavaScript with
`$` bound to the whole context:

```js
params: { quantity: '`$.pear.out.price * 2`' }     // 1.5
```

A literal backtick is written as `` \` ``.

## 4. Provide values up front with `context`

The `context` property of the spec is the initial reference context.
Its entries are referenced like call records, with the entry name before
the colon:

```js
module.exports = {
  pattern: 'role:shop',
  context: { cfg: { limit: 7 } },
  calls: [
    { pattern: 'cmd:list', params: { limit: '`cfg:limit`' }, out: [] },
  ],
}
```

## 5. Know where references are resolved

* In `params` given as an object, before the message is sent.
* In `out`, when the reply is checked. The record of the current call is
  stored before `out` is checked, so a call can reference its own reply,
  for example `out: { b: 'b0', c: '`self0:out.b`' }` in a call named
  `self0`.
* Not in `err`, and not inside Joi rules.
* A `params` function receives the context as its second argument and
  needs no backticks: `params: (call, context) => ({ id: context.pear.out.id })`.

An unknown name or a missing property resolves to `null`; a literal
match against it then fails with a message such as `"id" must be [null]`.
